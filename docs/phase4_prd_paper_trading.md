# 四期 PRD：模拟盘（Paper Trading）— 用真实时间线验证策略

> 质量节拍 Phase 0.3 产出 | v0.5.0 → v0.6.0
> 起因：回测只能回放历史，无法回答「这个策略在**当下**到底行不行」。

---

## 背景与问题定义

### 回测 vs 模拟盘

| | 回测（Backtest） | 模拟盘（Paper Trading，本期） |
|---|---|---|
| 时间线 | 一次性回放历史 N 年 | **按真实日历逐日推进** |
| 用途 | 快速评估参数 | **验证策略在真实环境中的可持续性** |
| 数据 | 全量历史（已知结局） | 每日只取到「今天」为止 |
| 心理 | 无 | 有——但资金是虚拟的 |

回测能筛掉明显不行的策略，但**筛不出「靠运气赢的历史」**。
模拟盘用真实时间线跑，才能验证策略是否稳定。

### ⚠️ 审查中发现的现有回测缺陷（本期必须避开）

在 `strategy/engine.py` 中定位到**未来函数**：

```python
current_df = df.iloc[: i + 1]        # 策略看到第 i 天（含）
result = strategy.analyze(symbol, current_df)
if result.action == ActionType.BUY:
    buy_price = current_price * (1 + self.slippage)   # 用第 i 天收盘价成交
```

策略在第 i 天**收盘后**才产生信号，却假设能在**同一天的收盘价**成交。
现实中不可能——这会系统性高估策略表现。

**模拟盘严禁复制这个错误**。

## P0: 核心账户与撮合引擎

### FR-P0-01: 账户模型（Account）

**状态**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `initial_capital` | float | 初始资金，默认 10000 |
| `cash` | float | 可用现金 |
| `positions` | dict[str, Position] | 各标的持仓 |
| `created_at` | datetime | 账户创建时间 |
| `pending_orders` | list[Order] | 已提交未成交的订单 |

**不变量**（必须有测试锁定）：
- `cash >= 0` —— 任何时刻不得为负
- `Σ 持仓市值 + cash == 总资产`
- 买入后 `cash` 恰好减少 `金额 + 佣金`

### FR-P0-02: 持仓模型（Position）

| 字段 | 说明 |
|------|------|
| `symbol` | 股票代码 |
| `shares` | 持股数量（100 的整数倍） |
| `avg_cost` | 持仓均价（**移动加权平均**） |
| `last_price` | 最新价 |
| `open_date` | 建仓日（用于 T+1 判定） |
| `frozen_shares` | 当日买入被冻结的股数（T+1） |

**浮动盈亏**：`market_value = shares × last_price`，
`profit_loss = (last_price - avg_cost) × shares`。

### FR-P0-03: 成交记录（Trade）

每次成交必须落库，字段：
`symbol / side(BUY|SELL) / shares / price / amount / commission /
stamp_tax / slippage_cost / signal_source / signal_confidence / executed_at`

### FR-P0-04: **T+1 次日开盘撮合**（核心防未来函数）

**规则**：
1. T 日**收盘后**运行策略，产生信号 → 生成**订单**（不是成交）
2. 订单在 **T+1 日开盘**以开盘价撮合
3. 若 T+1 无数据（停牌/非交易日）→ 订单顺延至下一交易日

```
T日收盘: 策略看 df[:T] → BUY 信号 → 挂单 pending
T+1日:   以 df[T+1].open 撮合 → 成交记录 → 持仓更新
```

### FR-P0-05: A 股交易规则

| 规则 | 实现 | 依据 |
|------|------|------|
| **T+1** | 当日买入的股票当日不可卖出 | A股制度 |
| **最小单位** | 买入必须 100 股整数倍 | A股制度 |
| **佣金** | 万 3（0.03%），最低 5 元 | 行业惯例 |
| **印花税** | **卖出** 0.05%，买入不收 | 2023-08 减半后 |
| **过户费** | 0.001%（双向） | 现行 |
| **涨跌停** | 主板 ±10%，创业板/科创板 ±20%；触及涨跌停**当日不撮合** | A股制度 |
| **停牌** | 无成交量则不撮合 | — |

> 涨跌停幅度按代码判定：`300`/`301`/`688`/`689` 开头为 ±20%，其余 ±10%。

### FR-P0-06: 资金约束

- 买入金额 + 全部费用 ≤ 可用现金，否则**拒单**（不部分成交）
- 单票持仓市值 ≤ 总资产 × `max_position_pct`（默认 20%）
- 卖出数量 ≤ 冻结后可用股数

## P1: 绩效与验证

### FR-P1-01: 绩效指标

- **总收益率** = `(总资产 - 初始资金) / 初始资金`
- **年化收益率**（按 252 交易日）
- **最大回撤** + **回撤持续期**
- **夏普比率**（无风险利率默认 0）
- **胜率**：盈利卖出笔数 / 总卖出笔数
- **盈亏比**：平均盈利 / 平均亏损
- **基准对比**：同期买入持有收益 + Alpha + Beta

### FR-P1-02: 资金曲线（Equity Curve）

每个交易日收盘记录：
`date / total_asset / cash / market_value / drawdown`

### FR-P1-03: 策略有效性报告

- 累计收益 / 年化 / 回撤 / 夏普
- 与「买入持有」基准的对比
- **明确标注样本期与交易笔数**——笔数太少（< 20）时结论不可信
  必须给出提示，避免用 3 笔交易就宣称策略有效

## P0（续）：状态持久化与定时运行

> 2026-10-10 完成。起因：模拟盘原本只能手动点，且引擎只在进程内存里 ——
> 定时跑的前提是**重启不丢状态**。

### FR-P0-07: 账户状态持久化

| 项 | 实现 |
|---|---|
| 落盘时机 | 每次 `step()` / `run()` 之后；`reset` 时删除 |
| 落盘内容 | `Account` 全量 + `_metadata`（股票池 / 取数区间 / **推进游标**） |
| 写入方式 | 先写同目录临时文件再 `os.replace`，避免半截文件 |
| 恢复 | 启动或首次访问账户时按 `account_id` 读取；损坏文件只丢该账户，不崩服务 |
| 文件位置 | `data/paper/{account_id}.json`（已加入 `.gitignore`） |

⚠️ **游标必须一起存**：`Account` 里没有「推进到哪一天」，那在引擎的
`_cursor` 上。只恢复账户不恢复游标，重启后 `step()` 会从数据区间开头重新推进，
在交易过的日期上再交易一遍 —— 资金曲线出现重复日期，而且**不报错**。

### FR-P0-08: 定时运行

| 项 | 实现 |
|---|---|
| 依赖 | `apscheduler>=3.10`（可选依赖 `[schedule]`），未安装时接口返回 **503** |
| 默认时间 | 每交易日 **15:30**（A 股 15:00 收盘后 30 分钟）推进 1 个交易日 |
| 周末 | 由 cron `day_of_week=mon-fri` **结构性排除**，不依赖任务内判断 |
| 节假日 | `data/paper/holidays.json`（**已随仓库提供 2026 年表**）<br>生成方式：`experiments/generate_holidays.py` 取 **baostock + akshare 两个独立源**的交易日历并**逐日比对**，不一致则拒绝写盘（fail-closed）<br>跨年后失效 → status 给出「已过期」warning 提醒重新生成 |
| 重入 | `max_instances=1` + `coalesce=True`：上一轮没跑完就跳过本轮；休眠错过只补跑一次 |
| 失败可见 | 成功 / 失败 / 跳过都写入可查询的 status（`run_count` / `error_count` / `skipped_count` / `consecutive_failures` / `last_error`），异常同时进日志 |
| 落盘失败 | 「跑成功但没存下来」按**失败**处理（否则会出现"每天都在跑、账却不动"） |
| 重启恢复 | 配置写 `data/paper/schedule.json`，进程重启后自动接回；缺依赖时显式报错而非静默失效 |
| 线程安全 | 定时任务在线程池执行、API 在事件循环执行，故每个账户一把可重入锁，防止同一笔挂单被撮两次 |

### FR-P0-09: 失败告警（2026-10-10 补）

定时运行的最后一块不是"每天自动跑"，而是"**跑挂了会有人知道**"。
没有告警时 `last_error` 摆在那儿，但没人会天天去看接口。

| 项 | 实现 |
|---|---|
| 通道 | 复用 `notify/`（控制台 / 文件 / Webhook，支持钉钉·飞书·企业微信），不另起传输 |
| 接口改动 | `NotificationChannel.send(message, result=None)` —— `result` 改为可选，系统告警传 `None`（告警没有 `StrategyResult`） |
| 配置 | `STOCK_NOTIFY_*` 环境变量 / `.env`，见 `.env.example`；**不改代码** |
| 触发 | 失败（含"跑成功但没落盘"）；**首次必发**，之后每 N 次（默认 3）再发一次；失败→恢复也发一条 |
| 不触发 | 非交易日跳过、正常成功 |
| 隔离 | 告警通道异常**不影响调度**（否则"通知挂了"会升级成"定时任务挂了"），原因记入 `last_alert_error` 与 status warning |
| 可见 | `GET /api/paper/schedule` 回显 `alert_channel`（Webhook **只显主机名**，URL 含 token 属凭据）/ `alert_count` / `last_alert_at` / `last_alert_error`；未接通道时给 warning |

**为什么不"一失败就发"**：连着一周失败会刷屏，通知被静音的下一步就是问题被静默。
节流消息里带累计失败次数，升级趋势仍然可见。

### FR-P0-10: 前端定时开关与状态卡（2026-10-10 补）

在此之前「每天自动跑」只能靠 curl —— 这是用户诉求的最后一格。

| 项 | 实现 |
|---|---|
| 位置 | 模拟盘 Tab 的**控件区**（与「开始模拟/刷新/重置」同一行带），数据卡片仍在下方保持主位 |
| 控件 | 执行时间（默认 15:30）+「开启定时」/「停止」/「立即执行一次」 |
| 状态 | 加载中 / 未开启 / 已开启（含**下次执行时间**）/ 上次成功 / 上次失败（含 `last_error` 原文与连续次数）/ 上次跳过 / 缺 apscheduler（**禁用按钮**并说明）/ 参数不合法 / 有 warnings / 查询失败 |
| 表达 | 状态用「**文字前缀 + 颜色**」双通道（`● 已开启`），不单靠颜色 |
| 原则 | **宁可显示坏消息，也不做"看起来在跑"的假象** —— 与后端「不静默失败」同源 |

**验证与缺口**（必须说清楚）：

- 本机用 Playwright **真实浏览器**验证 7 项（`experiments/verify_paper_ui.py`），
  含「非交易日点立即执行 → 如实显示未执行」
- ⚠️ **CI 跑不了浏览器**（未把 Playwright 纳入依赖）。CI 只有
  `tests/test_paper_schedule_ui_contract.py` 的契约锁：元素 id 两侧成对、
  按钮真的接了 click、CSS 类存在、**前端读的 status 字段确实由后端返回**（跨层锁）
- ❌ 布局、字号、可读性、交互时序 —— **契约测试测不到，别当视觉回归门禁**

## 技术方案

### 模块划分

```
src/stock_model/paper/
├── models.py       # Account / Position / Order / Trade / EquityPoint
├── broker.py       # 撮合引擎（T+1开盘价、涨跌停、费用）
├── engine.py       # 逐日推进流水线（step / run / report + 进度状态）
├── metrics.py      # 绩效计算
├── universe.py     # 动态股票池（三层筛选）
├── store.py        # 持久化（原子写 JSON，可换 SQLite）
└── scheduler.py    # 定时运行（APScheduler + 交易日/失败可见/配置落盘）
```

### 为什么独立于现有回测

现有 `BacktestEngine` 是**一次性遍历**设计；模拟盘需要**状态跨日持久化**、
订单生命周期管理，两者数据模型不同。强行复用会让回测的假设污染模拟盘。

### 持久化

默认 JSON 文件（`data/paper/{account_id}.json`），单账户场景足够。
预留 `store.py` 接口便于日后换 SQLite。

运行时文件（账户快照 / 定时配置 / 临时文件）**不进版本库**：
`.gitignore` 忽略 `data/paper/*`，仅放行**脚本生成**的 `holidays.json`（由两个独立数据源交叉验证，不手写）。

## 验收标准

- [ ] 初始 1 万元账户可创建，`cash == 10000`，无持仓
- [ ] 买入 100 股万科，扣款 = `price × 100 + 佣金 + 过户费`，余额正确
- [ ] 卖出时额外扣印花税
- [ ] **T+1 生效**：当日买入当日不可卖，尝试则拒单
- [ ] 订单在 T+1 **开盘价**成交，非 T 日收盘价（防未来函数）
- [ ] 买入金额超出现金 → 拒单，现金不为负
- [ ] 非 100 整数倍买入 → 向下取整到 100 倍
- [ ] 涨停/跌停日不撮合
- [ ] 佣金有 5 元下限
- [ ] 最大回撤、夏普、胜率计算正确（用构造数据验证）
- [ ] 交易笔数 < 20 时报告显式警告"样本不足"
- [ ] 全部 13 个 API 端点可用
- [ ] Web 界面 5 个区块可渲染
- [ ] **重启进程后账户/持仓/成交/资金曲线不丢**（端到端验证，见 `docs/HANDOVER.md`）
- [ ] 定时任务可开启/停止/查询，非交易日跳过且留痕
- [ ] ruff 0 errors，全量测试通过

## 明确不做（Out of Scope）

| 项 | 原因 |
|---|------|
| **真实券商下单** | 涉及资金安全，需独立立项与风控设计 |
| 融资融券 / ETF / 可转债 | 超出初始范围 |
| 分钟级 / tick 级 | 数据源只提供日线 |
| 投资组合级 T+1 全局风控 | 初期单标的验证已足够 |
| 多账户 / 账户间资金划转 | 非当前验证目标 |

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 样本太少就下结论 | 报告强制标注交易笔数，< 20 显式警告 |
| 未来函数让结果虚高 | 强制 T+1 开盘价撮合，并有测试锁定 |
| 幸存者偏差 | 不涉及（股票池由用户指定） |
| 数据源延迟/错误 | 复用现有 DataQualityMonitor，异常数据不入账 |
| 模拟结果被误认为真实业绩 | **UI 显著位置标注「模拟盘 · 非真实交易」** |
